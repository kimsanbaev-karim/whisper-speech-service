# Сервер голосового распознавания

Локальное распознавание речи на faster-whisper: модель живёт в памяти, ответ приходит по HTTP.
Аудио никуда не уходит — всё считается на своей видеокарте.

## Зачем

Раньше каждый вызов поднимал отдельный процесс и заново тянул с диска модель large-v3
(около трёх гигабайт): 19–26 секунд на короткое сообщение, а под нагрузкой (импорт Unity,
сборка) — падение по таймауту. Резидентный сервер убирает эту загрузку из каждого запроса:
1–2 секунды в диалоге, 15 секунд только на первом запросе после простоя.

## Что внутри

| файл | назначение |
|---|---|
| `server.py` | HTTP-сервер на стандартной библиотеке, порт 8792, модель в памяти |
| `transcribe.py` | разовое распознавание файла из командной строки |
| `tray.py` | значок в трее: держит сервер, перезапускает после падения |
| `make_icon.py` | рисует иконку — профиль говорящего человека |
| `install_autostart.py` | ярлыки на рабочем столе и в автозагрузке |

## Установка

```bash
uv venv
uv pip install faster-whisper pystray pillow pywin32
python make_icon.py
python install_autostart.py
```

Модель кладётся в `models/large-v3` и в репозиторий не входит, как и виртуальное окружение.

## Запуск

Ярлык «Распознавание речи (трей)» — поднимает сервер под надзором значка.
Без значка: `python -X utf8 server.py`.

## Как обращаться

```bash
curl http://127.0.0.1:8792/healthz
curl -X POST -H "Content-Type: application/json" \
     --data-binary '{"audio": "C:/path/to/voice.ogg"}' \
     http://127.0.0.1:8792/transcribe
```

Ответ: текст, язык с уверенностью, длительность и устройство.
Файл не найден — 400, распознавание упало — 500 с текстом ошибки.

## Поведение по памяти

Модель грузится по первому запросу и выгружается после 15 минут тишины: на машине,
где рядом живут Rider и Unity, три постоянно занятых гигабайта дороже, чем прогрев
раз в четверть часа. Порог — `IDLE_UNLOAD_SECONDS` в `server.py`.
